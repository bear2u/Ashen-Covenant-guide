### 계층 규칙

- `data/`는 다른 모듈을 거의 가져오지 않는 순수 표입니다.
- `rules/`는 `data/`만 씁니다. Three.js, DOM, `performance` 같은 브라우저 전역을 쓰지 않아서 Node에서 바로 테스트됩니다(입력 버퍼는 시계를 주입받음).
- `game/`과 `ui/`는 `rules/`의 함수를 불러 씁니다. 수치 계산을 `game/`이나 `ui/`에 새로 쓰지 말고 `rules/`에 넣은 뒤 테스트하세요.
- 프로필 변경 함수(`equip`, `sell`, `discard`, `transmute` 등)는 **전부 아니면 전무**입니다. 조건이 안 맞으면 아무것도 바꾸지 않고 `false`나 실패 사유를 돌려줍니다.

## 명령어

```sh
npm run dev          # 개발 서버 127.0.0.1:5173 (HMR)
npm run dev:lan      # 같은 네트워크에 공개 (휴대폰 접속용)
npm test             # 단위 테스트 132개
npm run build        # dist/ 생성
npm run preview      # dist/ 미리보기 127.0.0.1:4173

npm run qa:server    # 검증용 서버 5180 (HMR·파일 감시 없음)
npm run qa:checks    # 브라우저 검증 29종 (qa:server 필요)
npm run qa:mobile    # 휴대폰 에뮬레이션 터치 검증 16종 (dev 서버 5173 필요)
npm run qa:prod      # 프로덕션 빌드 확인 (preview 4173 필요)
npm run qa:bot       # 한 판 자동 플레이 (qa:server 필요)
npm run qa:campaign -- --build storm   # 새 캐릭터로 여러 판 자동 진행 (storm | ember)

npm run art:process  # 원본 이미지 → 처리된 프레임
npm run art:atlas    # 프레임 → 데스크톱·모바일 아틀라스
```

### 검증 서버 주의

`vite.qa.config.js`는 HMR과 파일 감시를 끈 설정입니다. 브라우저 검증이 자기 화면을 다시 불러오는 일이 없어 안정적이지만, **코드를 고친 뒤에는 검증 서버를 다시 켜야** 새 코드가 반영됩니다. 고쳤는데 검증 결과가 그대로라면 먼저 서버를 재시작하세요.

## 개발 방식

`plan.md`와 사용자 지침에 따라 TDD(실패하는 테스트 → 통과 → 정리)와 Tidy First(구조 변경과 동작 변경을 섞지 않음)를 따릅니다.

1. 규칙을 바꾸기 전에 `tests/`에 실패하는 테스트를 하나 씁니다.
2. 그 테스트만 통과할 만큼 `rules/`나 `data/`를 고칩니다.
3. `npm test` 전체를 돌립니다.
4. 화면 동작이 걸리면 `tests/e2e/checks.mjs`에 검증을 추가하고 검증 서버를 재시작해 돌립니다.
5. 구조 정리는 따로 하고, 정리 전후로 테스트를 돌립니다.
6. 커밋 메시지에는 구조 변경(Structural)인지 동작 변경(Behavioral)인지 적습니다.

## 데이터 추가하기

### 기반 장비

`src/data/bases.js`의 `BASES`에 `sword(...)` 또는 `wear(...)`로 추가합니다.

```js
sword('id', '이름', 단계(0~2), 품질레벨, 요구레벨, 힘, 민첩, [최소, 최대], 공속, 최대소켓)
wear('armor', 'id', '이름', 단계, 품질레벨, 요구레벨, 힘, [방어최소, 방어최대], 최대소켓)
```

- 아이콘은 `public/assets/icons/<id>.jpg`가 필요합니다.
- 기반 승급 경로는 `upgradedBase`가 자동으로 정합니다(같은 종류 다음 단계, 같은 공속 우선).

### 옵션

`src/data/affixes.js`에서 계열 하나를 `ladder(종류, 계열, 붙는종류, 등급목록, { freq, rare })`로 추가합니다. 등급은 `[이름, 옵션레벨, { 수치키: [최소, 최대] }, { rare: false }]`입니다. 수치 키는 `src/data/stats.js`의 `STATS`에 있어야 합니다(없으면 저장 검증에서 거부됨).

새 수치 키를 만들면 `STATS`에 이름을 넣고, 실제 효과는 `src/rules/character.js`(캐릭터 수치) 또는 `src/rules/combat.js`(피해)에 연결합니다.

### 고유·세트

`src/data/legendary.js`의 `UNIQUES` 또는 `SETS`에 추가합니다. `base`는 기반 ID, `lvl`은 등장 아이템 레벨, `req`는 요구 레벨, `stats`는 `r(최소, 최대)`입니다.

### 룬워드

`src/data/materials.js`의 `RUNEWORDS`에 `{ id, name, kinds: ['sword'], runes: ['rune-2', 'rune-1'], stats }`로 추가합니다. 룬 순서가 곧 넣는 순서이고, 룬 수 = 필요한 소켓 수입니다.

### 기술

`src/data/skills.js`의 `SKILLS`에 추가합니다. `values(level)`이 그 레벨의 수치를 돌려주고, 피해는 `range(level, [최소, 최대], [[a최소,a최대],[b최소,b최대],[c최소,c최대]])`로 레벨 구간 성장을 씁니다.

- 패시브라면 `src/rules/character.js`의 `addStats(stats, { … passive(...) })`에 연결합니다.
- 액티브라면 `src/game/player.js`의 `updateCast`에 발동을 넣고, 피해 함수는 `src/rules/combat.js`에 둡니다.

### 저장 형식을 바꿀 때

`src/rules/save.js`의 `validateProfile`과 `SAVE_VERSION`을 함께 고치고, 이전 버전을 옮기는 함수와 백업 키를 추가합니다. 손상된 저장을 절대 덮어쓰지 않는다는 규칙을 지켜야 합니다.

## 에셋

캐릭터·적·보스·이펙트·소품·아이콘·바닥과 벽 텍스처·타이틀 아트는 모두 이미지 생성으로 만들었습니다. 코드로 그린 대체 이미지는 쓰지 않습니다.

1. `art/prompts/*.txt`의 프롬프트로 생성한 원본을 `art/raw/`에 둡니다(배경은 단색 #FF00FF).
2. `npm run art:process`: 크로마키 제거, 프레임 분할, 발 기준 정렬, 품질 검사(`art/qc/`).
3. `npm run art:atlas`: 데스크톱 아틀라스와 0.6배 모바일 아틀라스(`public/assets/sprites/m/`)를 만듭니다.
4. `python3 art/tools/build_icons.py`: 아이콘 시트를 ID별 아이콘으로 자릅니다.

아틀라스나 텍스처를 불러오지 못하면 대체 이미지로 실행을 이어 가므로, 에셋이 빠져도 게임은 멈추지 않습니다.
